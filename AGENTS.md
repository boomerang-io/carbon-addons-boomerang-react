# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Stack

React component library built on Carbon Design System (`@carbon/react`), published as a dual CJS/ESM package. Package manager is **pnpm**. Build uses Rollup (components) + tsup (types) + a custom Node script for SCSS. Tests run with **Vitest** + jsdom + Testing Library + `jest-axe`.

## Commands

```bash
pnpm test                    # run all tests (watch mode)
pnpm test:coverage           # run all tests with coverage (single run)
pnpm run vitest src/components/Loading/Loading.spec.tsx  # run a single test file
pnpm lint                    # eslint src/
pnpm build                   # full build: cleans dist/, builds CJS, ESM, SCSS copy, and types
pnpm start                   # Storybook dev server on :6006
```

To run a single test file: `pnpm exec vitest run <path/to/File.spec.tsx>`

## Architecture

- `src/index.ts` — single public entry point; every exported component must be added here
- `src/components/<Name>/` — one folder per component; each folder has `<Name>.tsx`, `index.tsx` (re-exports default and `Props` type), optional `_name.scss`, `.stories.tsx`, `.spec.tsx`
- `src/internal/settings.ts` — exports `prefix = "cds"` used for Carbon CSS class names; import from here, never hardcode
- `src/config/servicesConfig.ts` — centralised axios service URLs and react-query `queryClient` (with `refetchOnWindowFocus: false` globally)
- `src/types/index.ts` — shared domain types (`User`, `Team`, `Navigation`, `FormInput`, etc.); import from `../../types`
- `src/tools/` — shared utilities (URL helpers, yupAst DSL for DynamicFormik validation, etc.)
- `src/constants/DataDrivenInputTypes.ts` — input type constants for `DynamicFormik`/`DataDrivenInput`
- `scss/` — SCSS copy output for consumers; generated by `pnpm build:styles`, do not edit manually

## Code Style

- **Props type**: exported as `Props` from each component file (`export type Props = ...`) and re-exported from `index.tsx`
- **Component default export** + named `Props` export from `index.tsx`: `export { default } from "./Foo"; export type { Props } from "./Foo";`
- **classnames** alias: `import cx from "classnames"` (package is named `classnames`)
- **CSS class names**: always use `prefix` from `../../internal/settings` — e.g., `` `${prefix}--bmrg-...` ``; SCSS uses `$prefix: "cds"`
- **IBM Confidential header**: every source file starts with a copyright block (lines 1-5); keep it when editing existing files
- `printWidth: 120` (Prettier)
- TypeScript strict mode; `tsconfig.json` has `baseUrl: ./src` with path alias `"*": ["./*"]`
- Commits follow Conventional Commits (`commitlint`)

## Testing

- Test files: `<ComponentName>.spec.tsx` **co-located** in the component folder (not a separate `__tests__` dir)
- Snapshots saved in `__snapshots__/` subfolder within the component directory
- Every spec should include a `snapshot` test and an `a11y` test using `axe` from `jest-axe`
- Setup file `src/setupTests.ts` imports `jest-axe/extend-expect` and `@testing-library/jest-dom`; vitest globals enabled so `describe`/`test`/`expect` are available without imports
- `matchMedia` must be manually mocked in tests that render components using Carbon's responsive utilities (see `UIShell.spec.tsx`)
- Stories can be imported directly into tests (`import { Story } from "./Component.stories"`)

## SCSS

- Component SCSS files use SCSS modules via `@use` (not `@import`)
- All component SCSS is aggregated in `src/global/index.scss` via `@use` — add new components there
- Two optional theme flags: `$use-theme-boomerang` and `$use-theme-advantage-white` (both `false` by default)
